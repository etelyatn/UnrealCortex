## Independent review

A read-only reviewer inspected the candidate against UE 5.8 source. Two P2 findings were reproduced
and fixed, then re-verified:

1. **Function signature names were not unique.** `UMaterialExpressionFunctionInput/Output::ValidateName`
   only scans a `UMaterial`, so it is a no-op for function-owned nodes; two Cortex-created outputs
   stayed `Result`. `add_node` now uniquifies against the function's expressions with the engine's
   own suffix algorithm (`Result_1`, `In_1`), and `set_node_property` refuses a duplicate
   `InputName`/`OutputName` with `INVALID_VALUE` before staging. Covered by
   `UniqueSignatureNames`.
2. **An open function editor kept a stale duplicate.** `RefreshGraphFromOriginal` no-ops while
   `GIsTransacting`, so calling `RefreshMaterialFunctionEditor` inside the command transaction would
   do nothing; the editor's Apply could copy its stale collection over the asset. Function graph
   writes now queue one deduplicated `RefreshMaterialFunctionEditor` call for the next tick. Source
   behavior verified in `MaterialEditingLibrary.cpp`/`MaterialEditor.cpp`; the open-editor visual
   path was not exercised in automation (no code path to Apply through the harness), so this fix is
   source-backed rather than scenario-proven.

The reviewer verified the rest as sound: material behavior, instance refusals before mutation,
batch recompile dedupe, pin fallback order, and override lookup.
