`Cortex.Material.Asset.CreateSaveFailure` declares the engine's refusal diagnostics as expected: per create, one `Cannot remove ... as it is read only!` error and one `Error saving` warning. It removes the blocking directories, the in-memory assets, and the temp files that the refused save leaves in `Saved/`. After the suite, no `*SaveFailure*` files remained under `Content/` or `Saved/`.

One `Cortex.Material+` run with the default 120 s cap stopped inside `Cortex.Material.Collection.DeleteCollectionRefusesReferencedWithoutForce`, after `Force Deleting 1 Package(s)`. There was no crash report. That test does not reach the changed code. Before that run and after it, the same suite on the same binaries passed 88/88 in under 60 s.

## Clang syntax gate

`cli/clang/clang-syntax-check.py` (changed files vs `origin/main`, the whole CortexMaterial module because `CortexMaterialInputUtils.h` changed): 17 units passed, with 0 errors and 0 warnings. The first attempt ran at the same time as an MSVC build that was rewriting the module response files. Only the new test unit failed, with `clang-cl: error: no such file or directory: '/dximplicitlyinstantiatevirtualfunction-'`, and every other unit passed. The re-run with no build running passed every unit, the new test unit included.

After each review correction the gate was re-run on the changed units. Final candidate: `CortexSerializer.cpp`, `CortexMaterialGraphOps.cpp` and `CortexMaterialUndoTest.cpp`, 3 passed, with 0 errors and 0 warnings.

## Independent review

A read-only reviewer subagent reviewed `b388afb6..28beeff4` and found one Important defect. Staging retired instanced sub-objects outside the transaction. Its review of the first correction found a reachable variant: an independent asset held by an instanced property was retired. Both findings were reproduced with failing tests and fixed. The reviewer's verdict on the final correction was "correct, ready to merge".

## Live editor (TCP line JSON through `cortex_mcp.tcp_client.UEConnection`, task-owned CortexSandbox editor, candidate before the review corrections)

Undo was triggered with `editor.run_python` → `TRANSACTION UNDO`.

- `create_material`, then two `add_node` (Constant3Vector, Multiply). The Constant3Vector was connected to `BaseColor` and to the Multiply's `A`.
- `remove_node` of the Constant3Vector removed the node and both connections. Undo restored the node and both connections.
- `set_node_property ConstB=3` changed the value from 1 to 3, and Undo restored 1. A `null` value returned `INVALID_FIELD` and left `ConstB` at 1.
- `create_instance` of that material, then:
  - `set_parameters` with one bad entry returned `INVALID_PARAMETER`, "No parameters were set (1 failed)". An empty array returned `INVALID_FIELD`.
  - `set_parameter Rough=0.7` added the override, and Undo removed it.
  - `reset_parameter Rough` removed the override, and Undo restored `Rough=0.4`.
  - `set_parameters` with A and B added both overrides, and one Undo removed both.
- The smoke assets were deleted, the task-owned editor was shut down, and the empty smoke folders were removed.

The `SAVE_FAILED` path was not exercised live; the native test covers it. The review corrections only affect writes that replace or clear an instanced value. `Cortex.Material.Undo.SetNodePropertyInstanced` covers them, and the Core and Data suites cover the serializer. For the primitive `ConstB` write exercised live, the corrections retire nothing.
