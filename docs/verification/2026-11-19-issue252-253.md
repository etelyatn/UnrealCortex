# Issues 252 and 253 verification: TCP desync recovery and composite warnings

Issues: https://github.com/etelyatn/UnrealCortex/issues/252, https://github.com/etelyatn/UnrealCortex/issues/253. Environment: Windows, Python MCP server only (no native source changed), base `d65108b9` (0.4.20).

## Issue 252: desync recovery returned a foreign response

`UEConnection._send_and_receive` read one extra line after a response id mismatch and returned it without checking its id. It now raises `UECommandDesyncError` when the recovered line also belongs to another request. The error subclasses `UECommandTimeoutError`: the command was already sent and its outcome is unknown, so `send_command` must not replay it, and existing callers that treat a timeout as "sent, status unknown" (`composites/gen.py`) handle it the same way.

| One-behind recovery (`test_tcp_safety.py::test_mismatched_id_reads_second_line`) | Passed, unchanged. |

## Issue 253: composites dropped native batch warnings

New `tool_output.batch_step_warnings(results)` collects every batch entry's non-empty native `warnings` as `{"step": index, "command": ..., "warnings": [...]}`. The success payloads of `level_batch` (`level_compose`), `create_blueprint_graph` (`blueprint_compose`), `create_widget_screen` (`widget_compose`), `create_material_graph` (`material_compose`) and `create_material_instance` (`material_instance_compose`) start their `warnings` list with these entries; the composites' own post-batch warnings (auto layout, save) are appended after them. When no step reports native warnings, nothing is added and payloads are unchanged.

Scope notes:

- `statetree_compose` does not send `batch`; it sends individual `statetree.*` commands, and the StateTree domain never sets envelope warnings (its validation warnings are data fields). Nothing is dropped there today.
- The native batch envelope carries no top-level `warnings`; only entries do (`CortexCommandRouter.cpp`, batch entry serialization). Only entries are read.
- Failure payloads are unchanged: the native router attaches `warnings` to successful entries only.

| GREEN: same tests | 5 passed; the material graph test shows the native step warning kept beside the composite's own `auto_layout` warning. |
