## Correction rounds (finite verification log)

1. `AppendRegistryDependentBlueprints` used `FARFilter.PackagePaths` (directory paths) where referencer **package names** were needed → `PackageNames`. Blueprint suite green after the fix.
2. Existing contract tests updated to the new opt-in contract: `Cortex.Data.ListDatatables` and `Cortex.Data.GetDataCatalog` TCP tests now pass `include_row_count=true` and keep asserting `row_count`/`top_fields`.
3. `Cortex.Data.DataCatalogNoLoad.Default` originally used a save/scan/unload fixture. The editor's async machinery (localization content validator reloading freshly created StringTables; registry unload events dropping freshly unloaded entries on the watcher's schedule — observed across five suite runs with pump lengths 0/10/25/100 ticks, before and after the unload) makes that fixture nondeterministic independent of the command. Redesigned onto stable project content (`/Game/Data/DT_TestSimple`, `/Game/Data/ST_TestStrings`) with an `AddInfo` skip if an asset is already in memory; test names sort before the two TCP contract tests that (by contract) load project tables. Deterministic across the final suite runs. The `ListDatatablesNoLoad` pair moved into the same `Cortex.Data.CatalogNoLoad.*` family (old names removed; no test uses them as a prefix).
4. The no-load property of the StringTable catalog branch is pinned indirectly (same `include_row_count` gate as the DataTable branch, whose no-load assertion is direct); the direct ST-unloaded assertion was removed with a comment — the localization validator reloaded the fixture in every variant tried.

## Behavior changes beyond speed

- `recompile_dependents` returns `COMPILE_FAILED` with per-dependent `results` in Details when any dependent fails to compile (previously success with an all-error array), and discovers dependents saved on disk but unloaded via registry referencers (`dependent_count == 0` after an editor restart is fixed).
- `list_datatables` / `get_data_catalog` omit `row_count`, `parent_tables`, `top_fields`, `entry_count` by default; `is_composite` stays (registry-derived). `schema_generator.py` passes `include_row_count=true` (it is the one consumer needing counts; explicit, on demand).
- `register_gameplay_tags` batch: one ini read+write per target file, one tag-tree refresh per batch. Within-batch duplicates and tags already present in the file (but not yet in the runtime tree) are reported `already_existed` — the realistic config-file behavior; the previous per-tag flow counted such duplicates as `registered` only when the per-tag refresh had already registered the first copy.
- `core.save_asset`: `was_dirty` is read from the loaded package only; the asset loads only when a save will happen; `dry_run` performs no load at all. An unloaded clean package reports `saved=true` without load (previously it loaded first; the response fields are unchanged).
- `core.batch`/`batch_query` capture the dirty baseline only when `rollback_on_error` is set (the baseline is read only by rollback verification, `CortexCommandRouter.cpp:283`).

## Independent review round

The reviewer-agent harness had no model configured this session, so the review was performed by the controller directly against the full production diff (findings verified against source before acting):

- **Fixed (real bug):** `GetMaterial` fed the referencer set into `FARFilter.PackageNames`; for a material with zero instances the set is empty, and an empty package-name list means "no constraint" — `instance_count` would have reported every MIC in the project. Guarded with an explicit empty-set check and pinned by a new assertion (`Cortex.Material.InstancesNoLoad.GetMaterialCount` now also creates an instance-less material and asserts `instance_count == 0`; Material suite rerun 92/92 with the fix).
- **Accepted tradeoff (documented in code):** `AppendRegistryDependentBlueprints` loads referencer BPs to check `ParentClass` (registry tags cannot express the child-of relation); non-child referencers stay in memory until the next natural GC.
- **Accepted tradeoff:** `rename_scs_component` error paths return before the batched GC; deferred garbage is collected by the next natural GC.
- Python diffs reviewed clean: invalidation coverage for the new cached read is auto-derived; the ping handshake preserves the failure semantics (same try/except).

## Slow-model review round (pre-merge, per maintainer request)

An independent model review ran over three slices (material+data, core+blueprint, Python) with the design doc as the contract. Every finding was verified against source before acting; dispositions:

- **Fixed — tag ini read failure:** the batch writer now fails its ini group without writing when an existing file exists but cannot be read (previously it would have replaced the file with a header-only version). `CortexGameplayTagOps.cpp` read handling.
- **Fixed — test strength (data no-load):** the catalog/list tests now always assert the response shape (default omission of `row_count`/`entry_count`, `is_composite` presence) and skip only the unload assertion when the project asset happens to be in memory.
- **Fixed — composite classification:** `is_composite` now resolves the registry class and uses `IsChildOf(UCompositeDataTable)` (matches the old loaded-cast semantics for subclasses), instead of comparing the exact class path, in both `list_datatables` and `get_data_catalog`.
- **Fixed — registry union gap:** `AppendRegistryDependentBlueprints` no longer skips packages that were absent from `GetDependentBlueprints`' snapshot but became loaded mid-loop (loading one referencer can pull another referencer package into memory); deduplication is on resolved Blueprint objects only.
- **Fixed — save_asset parity:** `asset_type` keeps its refined engine label for packages already in memory (no load), and the forced-save path re-checks `FindPackage` after asset resolution instead of re-entering `LoadPackage` unconditionally. (The reviewer's claim that the type was omitted entirely was incorrect — the registry-derived label was always present; only the refined label was lost.)
- **Fixed — core test:** the dry-run test asserts the data payload's presence independently of `bSuccess`.
- **Fixed — python test strength:** the router test now runs a real connection with a mocked transport, proves one transport call for two identical schema fetches, and proves a write drops the cached schema.
- **Accepted — tag write/refresh counting:** the batch test pins the final file contents and result totals; "exactly one write and one refresh" remains a code-reviewed property (no production test seam is added for it). The RED run's four vs three warning lines already distinguish the old per-tag verification path.
- **Accepted — the agent-harness model is the configured default tier; the `slow` tier is not configured in this environment** (subagent dispatch and `completion(model="slow")` both refused for lack of a model role).
