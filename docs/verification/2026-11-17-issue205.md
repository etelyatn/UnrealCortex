# Issue 205 verification: test-suite robustness

Issue: https://github.com/etelyatn/UnrealCortex/issues/205 (reported by @Boshchuk). Environment: Windows, UE 5.8 (installed engine), CortexSandbox, base `2aa17659` (0.4.17). Test code only; no production source changed.

## Reproductions on Windows

Runs launched directly (same flags as `cli/Testing/RunTests.ps1`, without its `Content/Temp/Cortex*Test*` pre-clean), so host-like preconditions apply.

Both instruments were reverted before the candidate build. |

Not reproducible on Windows, verified from source plus the reporter's Linux observations:

- Items 3 and 4: `CoCreateGuid` is random on Windows. On Linux `FUnixPlatformGuid::CreateGuidFromTimeAndRandom` (UE 5.8 `UnixPlatformGuid.cpp:43-60`) puts `ms >> 16` in `Guid.A`, so `Digits.Left(8)` stays the same for about 65 s. On Windows the reported sequence (`VerifyBlocked`, then `VerifyEnum`; `RenameWidgetDependents`, then `RenameWidgetDependentsBatchRollback`) passes on the candidate.
- Item 5: MSVC converts the out-of-range double to `INT_MIN`, so the old test passed by accident on Windows. The candidate sends 2147483648 and passes through the command's `RawIndex > INT32_MAX` branch.
- Item 6, Reflect/MigrationExport/redirector-warning tests: the Windows behavior (exact count 1, lock-based tests run) is unchanged, and the suites below pass. The Linux branches compile but were not run.

## Independent review

A read-only reviewer found no defects in the change. It noted a pre-existing production collision outside this issue: `CortexGenJobManager::GenerateJobId` (`CortexGen/Private/Operations/CortexGenJobManager.cpp:117-118`) takes `Left(8)` of the `Short` GUID form. On Linux that is the millisecond timestamp, so two jobs submitted in the same millisecond share an ID. Not changed here.

## Limits

- No Linux build or run. Linux-only causes rely on engine source and the reporter's observations. The Replay skip set comes from emulating the capability on Windows: 57 tests, where the reporter counted 52 (`Lifecycle` 43, `Window` 7, `RoundTrip` 2). The one extra `Window` failure on Linux could not be identified from Windows.
- `blueprint.compile` of a `__level_bp__:` path for a map that is not the editor world still leaves an initialized inactive world in production. The same ensure can follow a later GC. This is an engine destruction-order issue and is not changed here (design non-goal).
