## Live editor (line-delimited JSON over TCP, task-owned CortexSandbox editor, `get_status` project checked)

- `qa.observe_state {max_actors:-1}` returned `INVALID_VALUE` "max_actors must be a finite number >= 0".
- `qa.observe_state {max_actors:1000}` succeeded (8 actors in TestMap).
- `qa.wait_for {type:actor_hidden, actor:Floor, timeout:35}`:
  - The ack reported `timeout_seconds: 40`.
  - After 35.1 s it returned `condition_met:false, timed_out:true, duration_seconds:35.07`. At base the server's 30 s default would have cut it off.
- `qa.wait_for {type:delay, timeout:60}` acked with `timeout_seconds: 65`. `editor.stop_pie` was then sent on a second connection, and 0.9 s later the wait answered `PIE_TERMINATED` "PIE terminated during wait_for delay".

Base failure mode, observed by accident: an earlier `observe_state {max_actors:-1}` reached an unpatched 0.4.5 editor and killed it with the fatal error `Trying to resize TArray to an invalid size of 4294967295` at `CortexQAWorldOps.cpp:200`.

## Independent review

A source-only review raised two minor findings, both confirmed against the engine source and corrected:

1. Direct `move_to` stepped a fixed 0.1 s per ticker call. The core ticker fires at most once per frame and does not catch up, while the old looping world timer did (`TimerManager.cpp` CallCount). The correction advances by the PIE game time elapsed since the last poll, at the old 60 units per game second.
2. The test's PIE-stop deadline started when the latent command was queued rather than when it first ran. The correction starts it on the first run.

Re-review of the corrections found nothing.

Limit: the corrected direct-movement speed is not asserted by a test. The lifecycle test exercises the `move_to` poll only up to PIE termination. The correction was reviewed against `FMath::VInterpConstantTo`.
