## Live editor (line-delimited JSON over TCP; task-owned CortexSandbox editor on port 8743)

- **Deferred path still works.** `editor.wait_ready` completed through the deferred ack and completion. `editor.start_pie` returned `complete` with `{"state":"playing"}`, and `editor.stop_pie` returned `complete`.
- **Disconnect reaping.** Five clients each sent `get_status` and closed. Two seconds later, `Get-NetTCPConnection` on the editor PID showed none of them, and no `CloseWait` entry. Only the persistent control connection remained. The editor log shows a `Client disconnected` line for each closed client.
- **Request limit.**
  - 2,097,168 bytes without a newline: the client received `{"success":false,"error":{"code":"LIMIT_EXCEEDED",...}}`, and then EOF.
  - 2,097,153 bytes followed by a newline: `LIMIT_EXCEEDED`.
  - A `get_status` request of exactly 2,097,152 bytes succeeded with its `id`.
  - The control connection kept working.
- **Batch and PIE.** `batch` with steps `editor.start_pie` and `editor.get_pie_state` returned:
  - Step 0: `INVALID_OPERATION`, "start_pie requires a deferred response callback and cannot run inside core.batch".
  - Step 1: `stopped`.
  - Three seconds later, the PIE state was still `stopped`.
- The editor was shut down with `core.shutdown`.

The batch `details`/`warnings` fields and the deferred `TIMEOUT` code were verified natively only. Their router and serialization paths are the same ones the live route uses.
