# Issue #148 verification

## Scope and provenance

Windows, UE 5.8, CortexSandbox; base UnrealCortex commit
`fa54733d37daee5ae3eb8ca1f780c8f9f2af95d4`.
The fix rejects unsaved persistent maps before the engine's modal save path.
Linux reproduction is not available here.

## Recorded evidence

- Red: `Cortex.Level.Streaming.SaveLevel.NeverSaved`, rendering enabled,
  failed as intended: actual `INVALID_OPERATION`, expected `LEVEL_NOT_SAVED`.
  Raw log: sandbox `Saved/QA/Issue148/red.log`. Production behavior was unchanged.
- Python non-live suite: **936 passed, 265 deselected**, no warnings.
  `uv run --no-sync pytest tests/ -m "not e2e and not scenario and not stress"
  -q -p no:cacheprovider`; task-owned `--basetemp` and JUnit output.
- Final native build: **succeeded**, UE 5.8/Win64 Development; final incremental
  build produced no compiler warnings. Raw log: `Saved/QA/Issue148/green-build.log`.
- Rendering-enabled `Cortex.Level+`: **63 reported passes, 0 failures**, raw
  warning/error count **0**. Both `Streaming.SaveLevel` (isolated saved-map
  fixture) and `Streaming.SaveNeverSavedLevel` executed and passed. The unchanged
  `Streaming.SaveAll` case returned an informational skip because the startup
  map was locked; its save behavior was not exercised. Raw log:
  `Saved/QA/Issue148/green-level.log`; loaded `UnrealEditor-CortexLevel-0006.dll`.
- Python rerun against the final source tree: **936 passed, 265 deselected**,
  no warnings. JUnit: `Saved/QA/Issue148/python-final.xml`.
- Independent review found a residual source-control modal in `SaveLevel`'s
  dialog-enabled save output. The correction uses native non-dialog
  `SavePackages({Package}, false)`, preserving world/external/build-data saves.
  The reviewer confirmed resolution and found no further source/test findings.

An intermediate 62-pass native run exposed a test-name hierarchy collision:
the old `SaveLevel.NeverSaved` registration displaced the existing `SaveLevel`
case. The regression now has a sibling name. The next 63-test run exposed an
invalid saved-map fixture lacking `RF_Public`, causing the engine to treat its
package as empty. Corrected the fixture to normal map asset flags and added a
nonempty-package setup assertion; retained the dirty-state assertion. Both
failures and the final successful run are preserved under the task's QA root.

The first test build had a missing test include, corrected before the red run.
The first Python attempt encountered a locked MCP executable during environment
sync; using the existing environment avoids replacing it. A subsequent attempt
had 140 setup errors because the temporary-output parent directory did not
exist; creating the parent resolved them in the recorded complete run.

## Runner and limitations

Use a task-local copy of `cli/Testing/RunTests.ps1` with Level rendering enabled,
automatic content cleanup disabled, and historical log deletion disabled.
The shared runner incorrectly selects NullRHI for Level; it is not modified by
this PR. Native raw logs must be inspected independently of its exit status.
The full rebuild exposed **13 existing UE deprecation warnings** in unchanged
Core/Editor/Data/Reflect/StateTree source. These are compiler diagnostics,
separate from automation warning acceptance; see `Saved/QA/Issue148/full-build.log`.
The all-domain native suite, live TCP, and Linux reproduction were not run. Router
follow-up responsiveness is covered by the native regression, not a transport
benchmark. No GitHub CI checks are configured for this PR.

`save_all` and `open_level(save_current=true)` are unchanged: UE 5.8 fast-save
source skips packages without files, so their suspected Save As hang was not
validated. Their unsaved-package reporting is outside this change.
