## Decisions

### D1 Widget enumeration
CortexBlueprint gains private dependency `UMG` (CortexGraph already depends on UMG; no domain coupling). One private helper `CortexBPWidgetUtils::CollectWidgets(const UBlueprint*) -> TArray<UWidget*>` reads the `WidgetTree` object property by reflection (WBP class stays in UMGEditor, not linked), casts to `UWidgetTree` and calls `ForEachWidget` (includes named-slot content). Output order: tree pre-order (deterministic). Both `ExtractWidgetEntities` and the toolbar extension use it. No reader of `AllWidgets` remains. **Full tree:** `analyze_for_migration.widgets` emits EVERY widget of the tree (matching `umg.get_tree`), not only variable or event-bound ones; each row keeps `is_variable` and `bound_events_in_graph` so consumers can filter. `entity_summary` deliberately keeps its previous semantic for widgets: only variable widgets and widgets with graph-bound events (the entities a C++ migration must bind). `widget_dependencies` reads `entry_widget_class` from all rows (non-variable ListViews are now included). **`widget_dependencies`:** `references_widgets` is the sorted, deduplicated union of (a) the class path of every tree widget whose class is not under `/Script/` (Blueprint user widgets placed in the tree), (b) ListView `entry_widget_class`, (c) widget-class variable defaults/types. `referenced_by_widgets` is the sorted list of object paths of Widget Blueprint assets (WidgetBlueprint or subclass, e.g. EditorUtilityWidgetBlueprint) that reference this Blueprint's package, read via Asset Registry `GetReferencers` (package dependencies, hard and soft) with no asset loading.

### D2 analyze_for_migration output fixes
- `events`: never emit a `None` member name. `UK2Node_ComponentBoundEvent` emits `"<ComponentPropertyName>.<DelegatePropertyName>"`. Custom events stay only in `custom_events`.
- Function `outputs`: union of result-node user pins, deduplicated by pin name, first-seen order.
- `interfaces_implemented[].functions`: function-graph implementations plus ubergraph `UK2Node_Event` nodes whose `EventReference` member parent class is exactly the interface (not a parent or child interface: a child interface's event is listed only under the child). Entries stay strings (member name), deduplicated.
- `default_value`: a member variable with a non-empty description default reports that string unchanged. With an empty description default it reports the textual value of the property on the generated class CDO: bool → `"true"`/`"false"`, otherwise `FProperty::ExportText_Direct` with the value passed as its own delta. `ExportText_Direct` (Property.cpp) takes its `Data == Delta` branch and always exports, whereas a null delta would compare against the type default and export nothing for `0`/`""`/`None` values. Pinned engine output for untouched members: int `"0"`, FString `""`, FVector `"(X=0.000000,Y=0.000000,Z=0.000000)"`, object reference `"None"`. **Semantic change:** untouched non-bool members previously reported `""`; they now report the CDO value. Local variable with empty default and bool type → `"false"`; other empty locals unchanged (type default, as the editor shows).
- `input_bindings`: add `UK2Node_InputDebugKey` (lazy class lookup `/Script/InputBlueprintNodes.K2Node_InputDebugKey`, reflection reads) emitting `{ "kind":"debug_key", "key":<FKey name>, "modifiers":{ "ctrl","shift","alt","cmd" }, "execute_when_paused":bool, "trigger_events":["Pressed"|"Released" with linked exec] }`. Existing Enhanced Input entries unchanged; the early return only applies when neither class family exists.
- Unsupported-node rule: any `UK2Node` subclass, `EdGraphNode_Comment` and material graph nodes are supported, except that nodes of animation and state machine graphs (`Schema->GetGraphType` is `GT_Animation` / `GT_StateMachine`, the same test `graph_metrics` uses, one shared helper) keep counting as unsupported because `UAnimGraphNode_Base` derives from `UK2Node`. `unsupported_node_types` and the confidence penalty count those and any other classes.
- `has_tick` (per graph and in `complexity_metrics`) is true only for a **live** Tick event (D4 definition). Raw node counts in `complexity_metrics` stay unchanged; reachability metrics live in `graph_metrics`.

### D3 blueprint.list
- Params: `path` (unchanged), `type` (string), `exclude_types` (array of strings). Case-insensitive; unknown values → `INVALID_FIELD` listing the vocabulary. An empty-string or `null` `type` is treated as absent (routed callers send absent filters that way); `exclude_types: []` is fine. `type` and `exclude_types` may combine.
- Vocabulary (one shared classifier for AssetData and loaded BP): `Interface`, `FunctionLibrary`, `MacroLibrary` (BlueprintType tag), `AnimBlueprint` (asset class AnimBlueprint or child), `EditorUtility` (asset class EditorUtilityBlueprint/EditorUtilityWidgetBlueprint or native parent child of an editor-utility base), `Widget`, `Component`, `Actor`, `Object` (any other resolved UObject parent), `Unknown` (parent unresolvable). Precedence in this order.
- Rows add `native_parent_class` (short name of NativeParentClassPath) and `asset_class`; `parent_class` becomes the immediate parent (ParentClassPath) and `parent_class_path` its object path. An Asset Registry tag value of `None` (or empty) yields empty `native_parent_class`/`parent_class_path`/`parent_class` (a missing native tag falls back to the parent tag and vice versa).
- **Unified identity across commands.** `list`, `get_info`, `analyze_for_migration` and `create` share `FCortexBPAssetOps::DetermineBlueprintType` (type) and `ParentClassDisplayName` / `NativeParentClassName` (parents). `type` is always from the vocabulary above: analyze no longer emits `"WidgetBlueprint"` (Widget Blueprints, including EditorUtilityWidget Blueprints, report `Widget`/`EditorUtility` like list). `parent_class` is the immediate parent display name: the class name, with `_C` stripped only for Blueprint generated classes outside `/Script/` (a BP child reports its parent Blueprint asset name, a native parent reports e.g. `Actor`). `native_parent_class` is the short name of the nearest native ancestor; get_info and analyze add it. `parent_class_path` stays the exact class object path (analyze, list). `create` reports `parent_class` through the same helper.
- `create` keeps its five creatable types; get_info/analyze report the new vocabulary.

### D4 blueprint.graph_metrics (new, read-only)
Request `{asset_path, thresholds?: {max_nodes_per_entry: int=10, max_nodes_per_blueprint: int=30}}`.
Definitions:
- Graph scope: every `UbergraphPages` and `FunctionGraphs` graph plus every `ImplementedInterfaces[i].Graphs` graph (interface function implementations, entry kind `function`, name = graph name). Only graphs whose schema `IsChildOf(UEdGraphSchema_K2)` are measured (this includes `UWidgetGraphSchema`, used by Widget Blueprint function/event graphs), excluding graphs whose `Schema->GetGraphType(Graph)` is `GT_Animation` or `GT_StateMachine` (pose-flow networks without event/exec semantics; asked of the schema, so no animation-module dependency). AnimGraphs and state machine graphs produce no entries and no `unreachable` rows. Macro graphs (`MacroGraphs`) are never measured on their own; they count only where a macro instance expands them (below). Entry node: node with ≥1 exec output pin and no exec input pin (events, custom/bound/input events, Enhanced Input and debug-key nodes, function entries) in those graphs.
- Live entry: enabled (`Node->IsNodeEnabled()`: a `Disabled` node never runs; `DevelopmentOnly` counts as enabled in the editor) and either a function entry (always) or an entry with a linked exec output. A default ghost event is disabled (`MakeAutomaticallyPlacedGhostNode`, EdGraphNode.cpp:1132) and Kismet2.cpp:716-741 links its `then` to an auto-placed, also disabled, `CallParentFunction`: it is therefore a ghost entry even though its exec output is linked.
- Reachable set of an entry: pin-level exec reach from the entry (`CortexBPGraphExecReach`, `FReachContext`), then the backward data closure over input pins; `delete_orphaned_nodes` keeps its own seeding (`GatherExecForward`, no enabled filter). A disabled node is never reached (never functional) but execution passes through it exactly as the compiler does when it removes a disabled node (`FEdGraphUtilities::CloneGraph` relinks its incoming exec links to `GetPassThroughPin`, which `UK2Node` supplies only for exactly one exec input and one exec output): a disabled one-in/one-out node is transparent, a disabled node with several exec outputs (Branch, Sequence) has no passthrough and blocks the flow, and a disabled entry seeds nothing. For function entries, `UK2Node_FunctionResult` nodes that are not exec-reachable seed the closure only when the function is pure or its single result node has no exec link while the entry's `then` is unwired (the return value is then computed by its pure feeders); any other exec-unreachable result and its feeders are reported `unreachable`.
- Functional node: reachable, enabled, not the entry itself, not `UK2Node_FunctionResult`, comment, or `K2Node_Knot`. Disabled nodes (excluding comments/knots, entries included) are never functional and are reported in `disabled_nodes` / `disabled` rows instead of `unreachable`. Macro instances and collapsed (composite) nodes are replaced by the functional-node count of the nodes their inner graph reaches (recursively, cycle-guarded), routed by pin as `UEdGraphSchema_K2` expands tunnels (matching name, opposite direction): an exec input of the instance enters the inner graph only through the entry-tunnel output pin of the same name, and only the exit-tunnel inputs that execution reaches continue through the instance output pins of the same name. Each reached instance owns its own context (never shared between instances of one graph); the Blueprint totals merge the contexts of all live entries per graph, so each inner node counts once. An inner graph reached only through data (a pure macro) is seeded from its exit tunnel(s) and the backward closure. Tunnels, comments, knots and disabled nodes are never counted. Inner nodes that no live context reaches are reported once per inner graph in `unreachable` rows with `subgraph`; disabled inner nodes in `disabled` rows. An expandable node whose inner graph cannot be resolved counts as one functional node; a recursive instance (its graph is already being expanded above it) adds nothing.
- Conditionals: `UK2Node_IfThenElse`, any `UK2Node_Switch` subclass, `UK2Node_Select`, impure `UK2Node_DynamicCast`, plus conditionals inside expanded macros/composites.
- Getter fan-out: for each reached `UK2Node_VariableGet`, in the entry's root context and in every expanded context, the number of distinct consumer nodes of its outputs; a wire into an expanded instance continues to the consumers of the matching entry-tunnel pin inside it, and a wire into an exit tunnel continues to the consumers of the matching instance output pin outside, so collapsing logic neither hides getters nor changes fan-out. Report `max_getter_fanout` and `variable_gets`.
- `thresholds`: `null` is absent; an unknown key is `INVALID_FIELD` naming the key; known keys must be positive integers (a `null` value is absent).
Response:
```
{ asset_path, has_tick, totals:{functional_nodes, unreachable_nodes, disabled_nodes, ghost_entries, entries},
  entries:[{graph, name, kind:"event"|"function"|"input"|"custom_event"|"bound_event", node_id, live,
            functional_nodes, conditionals, variable_gets, max_getter_fanout}],
  unreachable:[{graph, subgraph?, count, node_ids:[...≤50]}],
  disabled:[{graph, subgraph?, count, node_ids:[...≤50]}],
  ghost_entries:[{graph, name, node_id}],
  thresholds:{...}, violations:[{scope:"entry"|"blueprint", graph?, name?, functional_nodes, limit}] }
```
Ghost (non-live) entries report `functional_nodes:0`. `has_tick` true iff a live ReceiveTick entry exists. `disabled` rows have the same `{graph, [subgraph,] count, node_ids}` shape as `unreachable`; rows for macro/composite inner graphs carry `subgraph` (the macro graph name / composite bound graph name) and `graph` is the graph that holds the expanding node.

### D5 graph.search_nodes inventory
- `graph_name` restricts to that graph (with `subgraph_path` as today).
- All filters optional; no filter returns every node (compact rows) of the selected scope. Python already pages `results` via cursor (`CACHED_PAGE_ARRAYS`), giving the paged inventory.
- `node_class`: case-insensitive; matches the node class or any superclass name (leading `U` optional on exact names only) — `K2Node` returns all K2 nodes; a trailing `*` means prefix match on the runtime class name, used verbatim (never `U`-stripped: `U*` matches runtime names starting with `U`, it is not an empty prefix).

### D6 data.get_struct_schema
Accept short name, `F`-toggled name, or object path. Factor CortexDataSchemaExportOps' `ResolveStructByName` into a shared CortexData private helper; for object paths under **any mounted package root** (`/Game`, plugin and engine content) load the struct only after `FPackageName::IsValidLongPackageName` (read-only roots allowed), a mounted-root check (`GetPackageMountPoint`), `FPackageName::DoesPackageExist` and an Asset Registry class check that the asset is a `UScriptStruct`; non-struct assets are refused without loading.

### D7 analyze_for_migration `sections`
Optional `sections: array[string]`; omitted/empty = all. Unknown names → `INVALID_FIELD` before any output. Prerequisite sections are computed internally and only selected sections are emitted (identity fields `name, asset_path, type, parent_class, native_parent_class, parent_class_path` always present). Python adds a complete-or-refuse policy for `blueprint.analyze_for_migration` suggesting `sections`, and likewise for `blueprint.graph_metrics` (suggesting `analyze_for_migration` with `sections=['complexity_metrics']` or a smaller Blueprint).

## Post-merge hardening (final review of merge b2b3ea2c, 2026-11-05)
Findings of the final review that changed semantics (the corresponding D-sections above were updated in place):
- **Disabled and ghost nodes (D4):** liveness and reachability honour `Node->IsNodeEnabled()`. `IsNodeEnabled` (not `GetDesiredEnabledState`) is the "will compile" predicate: `DevelopmentOnly` nodes are enabled in the editor. `IsLiveEntry` and the pin-level reach (`FReachContext`) take it into account; `has_tick` in `graph_metrics`, `analyze_for_migration` (per graph) and `complexity_metrics` follow. Linking a ghost through the schema converts it into a real node (`UEdGraphPin::ConvertConnectedGhostNodesToRealNodes`, EdGraphPin.cpp:1976), so a ghost event keeps its linked, disabled parent call only as created by `AddDefaultEventNode` (link first, then `MakeAutomaticallyPlacedGhostNode`). `delete_orphaned_nodes` is unchanged: it keeps the enabled-agnostic `GatherExecForward`/`ExpandToLinkedDataDependencies`. Execution passes through disabled one-in/one-out nodes (see the follow-up section below).
- **Macro/composite expansion (D4):** reachability-aware (entry-tunnel seeded, later made pin-aware) instead of counting every inner node; inner orphans surface as `unreachable` rows with `subgraph`.
- **Supported-node rule (D2):** animation and state machine graph nodes stay unsupported.
- **Function results (D4):** only exec-reachable, pure-function or sole-unwired results seed the closure.
- **Smaller contract points:** `blueprint.list` empty/`null` `type` is absent (D3); interface events are attributed only to their exact declaring interface (D2); `thresholds` unknown keys are rejected and `null` is absent (D4); `node_class` prefix filters are never `U`-stripped (D5).
- **`analyze_for_migration.type` consumers:** `Widget`/`EditorUtility` replaced `WidgetBlueprint`. In-repo consumer `CortexConversionPromptAssembler::SelectFragments` now matches `"type":"Widget"`; its test fixtures use the real output shapes. The toolkit sync (#74) must update its own consumers.
- **Locals `default_value` (D2, review item 8) — no code change:** function-local variables have no CDO, so a non-bool local with an empty description default keeps `""` (the type default, as the editor shows). Only member variables report the CDO text. Consumers that need to distinguish "explicitly set" from "engine default" for members cannot; this is a documented, accepted consequence of D2.
- **Standalone `graph_search_nodes` docstring:** states that the standalone tool does not page; bounded cursor paging is the routed `graph_cmd search_nodes` path (`CACHED_PAGE_ARRAYS`).

## Slow-model review follow-up (2026-11-05)
An independent post-merge review of merge `b2b3ea2c` (PR #190/#191) found three `graph_metrics` defects, all confirmed against the source and the UE 5.8 engine source and fixed in this follow-up (D4 above amended in place):
- **P1 disabled passthrough.** `FEdGraphUtilities::CloneGraph` (`EdGraphUtilities.cpp:302-331`) relinks a disabled node's incoming exec links through `UEdGraphNode::GetPassThroughPin` before removing it; `UK2Node::GetPassThroughPin` (`K2Node.cpp:2045-2090`) provides one only for exactly one exec input and one exec output. The metrics now traverse through that pin: the disabled node stays non-functional and reported as disabled, the downstream nodes count and are no longer `unreachable`, ambiguous disabled nodes (multi-output) still block, disabled entries still seed nothing. `DisabledNodeInLiveChain` had encoded the wrong expectation and was corrected.
- **P2 tunnel routing.** Inner graphs were seeded from the whole entry tunnel node, so a macro with several exec inputs charged every internal branch to an event wired to one input, and every exit continued. Reach is now pin-aware (see D4) per instance context.
- **P2 getters.** Getter counts and fan-out were measured only in the outer graph; they now cover every expanded context with boundary edges translated.
Implementation: `CortexBPGraphExecReach.{h,cpp}` (`FReachContext`) replaces the `bEnabledOnly` BFS/closure parameters of `CortexBPGraphReachability`, whose remaining helpers (`GatherExecForward`, `ExpandToLinkedDataDependencies`, `IsEntryNode`, `IsLiveEntry`, `IsAnimationOrStateMachineGraph`) keep their behaviour for `delete_orphaned_nodes` and liveness. Tests: `GraphMetrics.DisabledNodeInLiveChain` (corrected), `.DisabledMultiOutputBlocks`, `.TunnelPinRouting`, `.GettersAcrossExpansion`; existing macro/composite fixtures now use tunnels with real, name-matched pins and exits.
