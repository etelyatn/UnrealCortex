# PR #143 Unix file SHA-256 implementation

## Files and invariants

- `Source/CortexCore/CortexCore.Build.cs`: Unix-only engine OpenSSL private static dependency; define `CORTEX_SHA256_OPENSSL=1` for Unix and `0` otherwise. Existing Windows BCrypt library remains unchanged.
- `Source/CortexCore/Private/CortexSafeFileContract.cpp`: third-party OpenSSL SHA header only for the new backend, then single `SHA256(bytes, byte_count, digest)` with explicit failure handling. Append lowercase hex digits to reserved output without 32 temporary formatted strings. Retain safe-file guards and existing Windows/unsupported branches.
- `Source/CortexCore/Private/Tests/CortexSafeFileContractTest.cpp`: retained contributor known-answer fixtures for `abc` and empty input.
- `UnrealCortex.uplugin`: version 17 / 0.3.5.

## Verification sequence

1. Native Windows/MSVC build of the delivered platform selection; run existing safe-file suite and import-queue consumer coverage.
2. Temporarily enable engine OpenSSL for Win64 and route the two `#if PLATFORM_WINDOWS` backend selectors in this owner to the OpenSSL body. This is verification instrumentation, not a permanent platform-support change. Build and run the same native safe-file and import-queue paths; no mock FString, fake filesystem, or substituted hash implementation.
3. Restore original Windows-precedence selectors and Unix-only Build.cs dependency. Rebuild and run normal Windows known-answer and consumer coverage. Never commit the temporary selection or libraries.
4. Independently review platform wiring and safe-file/test behavior. Record native results plus unavailable Linux UE verification explicitly.
5. Exercise the delivered Windows build through actual TCP routing: preview a file-backed operation against a sandbox DataTable, compare summary/report hashes with an independent digest of the exact queue bytes, and query the row again to prove no mutation. Remove only owned queue/report inputs; retain smoke evidence.
6. Run the final native rendering `Cortex+` acceptance matrix. Keep existing runner failures, unrelated warnings, optional skips, and the unavailable Linux runtime distinct from successful test completions.

## Scope and synchronization

No exported API, command/schema, MCP Python, capability, durable-format, or domain-boundary changes. Toolkit synchronization is intentionally unnecessary. The existing engine OpenSSL platform policy is the authoritative dependency convention; no new external dependency or bundled cryptographic source.

Documentation and exercised evidence are recorded in the associated design and verification report. Contributor native Linux tests were reported against UE5.8.2 stacked on #136; they are not promoted to local maintainer proof.
